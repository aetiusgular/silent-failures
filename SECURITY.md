# Security

Open items, rendered into the README in P6. Severity: high, medium, low.

| ID | Severity | Item | Owner | Workaround | Status |
|---|---|---|---|---|---|
| T-1 | low | `ci` runs the PR's own copy of `ci.yml`, so a PR that edits it could post statuses with the workflow token. | Tony | `forge/guard` (base copy) fails any PR that touches `.github/`, and review reads the diff. | open |
| T-2 | low | gitleaks honours inline `gitleaks:allow` comments; a PR could mark a line as allowed. | Tony | Review greps the diff for `gitleaks:allow`. | open |
| T-3 | low | Under the box's `landlock` profile, TCP rules name ports, not addresses: the model port and the proxy (ephemeral) port range are open to any host, not only 127.0.0.1. | Tony | Only for projects with `eval_boundary: landlock`; the box's nftables rules and the proxies' own allowlists still apply. | open |
| T-4 | low | Task setups include shell scripts (`tools/regen.sh`, `tests/check_task.py`) that the agent under test is asked to run, and `record()` (lane P3a) runs the agent as a subprocess. | P3a, P5 | They run only inside the box's `srt` boundary (`eval_boundary`), in a fresh scratch work folder, with network limited to the local model and the stubs. ci runs neither. `record()` spawns argv directly with no shell, and writes its trace to a fresh temp folder that it removes. | open |
| T-5 | low | `oracle/evaluate.mjs` reads paths named in task files. | P2 | It refuses absolute paths and `..` segments (`tests/unit/oracle.test.mjs`). Task files are committed, and heldout ones are hash-frozen. | mitigated |
| T-6 | low | `toTargetTrace` and `toOtlp` (lane P3b) copy tool inputs, outputs, errors, file paths and exec argv into the trace. If a trace is ever sent to a hosted service, those fields could carry what the agent saw. | P3b, P5 | Both functions only return objects and send nothing. Written bytes are left out (`src/spans/spans.test.mjs`). The tasks use made-up entities only. Sending a trace anywhere needs a key, which goes through the section 8 process. | open |
| T-7 | low | The default trace folder (`mkdtemp` under `TMPDIR`, mode 0700) belongs to the same user as the agent, so outside a sandbox the agent could rewrite its own trace and fake effects (SL-P4-r0-S2). | P5 | `record()` refuses a `traceFile` inside the work folder. P5 checked the box: forge's `srt` profile lets the whole eval write the project checkout and `FORGE_TMP`, and the agent runs inside that same sandbox. So the agent **can** reach its trace (`FORGE_TMP/runs/<run>/trace.strace`), the stub log beside it, and the results folder. The ground truth does not read the trace. It does read the stub log, so since P5 round 2 the harness rewrites `stub.jsonl` from the stub servers' own memory after the run and before the oracle reads it (SL-P5-r1-S1, `tests/unit/harness.test.mjs`). What is left: the check's labels could be faked through the trace, and the agent could write files under `results/` (for example `results/audit/tony.jsonl`) that a session might then commit. Review the results diff before committing it. The fix is a per-run inner boundary for the agent alone (`derm run --boundary srt` per run). That is not built yet: P5 round 2, or a Request for forge's sandbox. | open |
| T-8 | low | `record()` reads the whole trace into memory, so a run that writes heavily can exhaust the harness's memory (SL-P4-r0-S3). | P5 | `timeoutMs` bounds the run. A failure is loud: the run errors and is not mislabeled. | open |
| T-9 | medium | `record()` passed the harness's whole environment to the agent under test (SL-P4-r0-S1). | P4 | Fixed: the default env is only `PATH`, `HOME`, `LANG`, `LC_ALL`, `TERM` and `TMPDIR` (`tests/integration/security.test.mjs`). | mitigated |
| T-10 | low | The P5 harness runs the agents under test with their permission prompts off: Claude Code with `--dangerously-skip-permissions`, and pi with no gate extension. | P5 | Every run is inside forge's `srt` profile: network limited to 127.0.0.1 through srt's proxy, writes limited to the checkout and `FORGE_TMP`, and credentials read-denied (forge `sandbox/run-eval.sh`). Each agent gets its own `HOME` and config folder under `FORGE_TMP`, so the box user's `~/.claude` and `~/.pi` are not read. The model pass-through (`harness/model-proxy.mjs`) listens on 127.0.0.1 inside the sandbox only. | open |
