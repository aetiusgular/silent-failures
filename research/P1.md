# P1: research and compare

Phase P1 of silent-failures (code SL). Every claim below gives its source and a short verbatim quote. Unless a line says otherwise, every source was read on **2026-11-23**. The starting brief is `forge/briefs/SL.md`. It stays in forge and is not copied here. Each brief claim is re-checked in section 1.

Words used here:
- **silent failure**: the agent's final report says the task succeeded, but the end state says it did not.
- **effect**: an OS-level act: a file open/write/rename/unlink, an exec, or a connect. It is recorded outside the agent.
- **trace-only check**: comparing the agent's text with the tool outputs the agent's own SDK recorded.

## 3. Have/lack: the three features this project is about

| Company | F1: OS-level effects recorded | F2: success claims checked against effects | F3: change gated on run-to-run variance |
|---|---|---|---|
| **Lemma** | **Lacks.** It records only spans the SDK reports. Even across processes the child "records a journal (local span, tool, and generation records)" (https://docs.uselemma.ai/tracing/instrumentation/cross-process-turns.md). Searched the docs index, changelog (https://docs.uselemma.ai/changelog.md), blog and repo. | **Has, trace-only.** "Compare the assistant text to the tool results and span outputs in the same run. A mismatch between those two panels is the defect." (turning-issues-into-fixes.md). Their own taxonomy names the gap: traces "don't tell you what was supposed to execute and didn't, or that the agent said it did" (https://www.uselemma.ai/blog/a-taxonomy-of-agent-failures). | **Lacks.** The monitor contract only defines a rate: "`rate` is `fit_count` divided by `traces_seen`" (https://docs.uselemma.ai/reference/monitor-contract.md). A fix is verified with "at least one new ready trace". |
| **Raindrop** (Workshop) | **Lacks.** https://www.raindrop.ai/docs/sdk/tracing/: "Record spans, tool calls, model calls and sub-agents inside an interaction". Simulations stub tools: "Tools and external services \| Simulated". | **Lacks** (not found in the tracing docs, Signals, Simulations or the Workshop repo). | **Lacks.** The loop "re-runs until every assertion passes". | **Ghost** | Not applicable (an on-device box). | Not applicable. | **Lacks** (not found). https://launchboosts.com/blog/ghost-core-personal-ai-computer-specs-explained: "Ghost hasn't published throughput numbers or the quantization levels it uses." That is a third-party page. |

| **Preference Model** (Karotte) | **Partial.** It hardens the end state rather than recording effects: "Any suspicious files, like FIFOs, symlinks, or large sparse files, get rejected" (introducing-karotte). `collect_submission` "kills every process the student owns" (https://www.preferencemodel.com/blog/karotte-a-technical-deep-dive/). | Not its job: it grades the submission. | **Lacks** (not a rerun tool). |
| **Prime Intellect** (verifiers) | **Partial.** Graders read the end-state filesystem: "a fresh container … giving graders a clean filesystem containing only declared agent outputs and private test assets" (https://docs.primeintellect.ai/verifiers/building-environments). | Not its job. | **Lacks** (not found). |

**Is effect recording as OTel spans a clone?** Not today, but close.
- AgentSight (eunomia-bpf, MIT) records agent file, process and network activity with eBPF: "Monitor active sessions, processes, resource, model and tool calls, file and network activity." (https://eunomia.dev/agentsight/).
- Its OTel export covers LLM calls only: "Tool/workflow spans (`execute_tool`, `invoke_agent`, `invoke_workflow`, `plan`) are not emitted yet" (https://raw.githubusercontent.com/eunomia-bpf/agentsight/master/docs/otel.md).
- A3S-Lab/Observer (MIT) writes NDJSON, and "in-process OTLP is intentionally **not** built" (https://github.com/A3S-Lab/Observer).
- OTel's eBPF instrumentation covers network and GenAI API calls, not agent file or process effects (https://opentelemetry.io/docs/zero-code/obi/).
- Searched: Exa ("eBPF syscall tracing of AI agents exported as OpenTelemetry spans"), the AgentSight repo, docs and PR #49, Observer, OBI docs and arXiv. Tetragon and Falco were not checked; both are general-purpose.
- **Consequence:** the recorder and spans are the plumbing, not the claim. The claim is the silent-failure check and its number (section 5).

## 4. Competitor comparison: Lemma against two eval tools

| | Lemma | Braintrust | Langfuse | This build |
|---|---|---|---|---|
| OS effects | Lacks (section 3) | **Lacks.** A traced function's span has "Function arguments as input; Return value as output" (https://docs.braintrust.dev/instrument/trace-application-logic) | **Lacks.** "Each trace captures every operation — LLM calls, retrieval steps, tool executions, and custom logic" (https://langfuse.com/docs/observability/overview) | strace -f plus an io_uring audit rule, joined to tool calls, emitted as spans |
| Success checked against effects | Trace-only text-vs-tool-output check | **Trace-only.** `agentAssertionScorer` "reads tool call spans from the trace automatically" (https://docs.braintrust.dev/sdks/typescript/api-reference) | Not found (generic evaluators, not read in detail) | Final report checked against recorded effects and the task's end state |
| Variance gating | Lacks | **Partial.** "Run each input multiple times to measure variance and get more robust scores." No k-of-n rule or interval gate found (https://docs.braintrust.dev/evaluate/advanced-evaluations) | **Lacks.** "Langfuse currently assumes that experiments do not contain repetitions" (https://langfuse.com/docs/evaluation/experiments/data-model) | A band gate from repeated runs blocks a change whose gain sits inside the band |

**Where the build sits:** below Lemma's tracing layer, not beside it. Its spans map into Lemma's `tool` span type. Its check covers the case Lemma's own taxonomy says traces cannot see: the agent said it did something, and nothing happened. The band gate is a second, smaller piece. Neither Lemma nor Langfuse has one, and Braintrust stops at averaging trials.

## 5. Three candidates, scored (BUILD_OUTLINE.md section 2)

Scores are relative to the target, Lemma.

### A. Effect check for silent failures, with spans and a band gate (the brief's build)
The recorder joins effects to tool calls and emits them as spans that fit Lemma's trace contract. A check flags runs whose final report claims success that the effects contradict. A band gate blocks a prompt change whose gain sits inside the run-to-run band.

| Criterion | Score | Evidence |
|---|---|---|
| Their customers feel it | 5 | The product is sold on this: "catch silent AI agent failures in production" (press release, B1). Their taxonomy says traces "don't tell you … that the agent said it did". |
| Not a clone | 4 | Lemma lacks F1 and F3 and has F2 only trace-only (section 3). Places looked: docs index, changelog, blog, repo, launch post and YC page. AgentSight records effects but has no tool spans (section 3). Not 5 because AgentSight could close that gap. |
| Tony has proof | 5 | derm's truth recorder (`tests/eval/lib/truth.mjs`, strace plus an io_uring rule, B5), derm's effect-visibility evidence (`docs/evidence/effects/2026-11-12/`), and derm's 300-run k-of-3 benchmark (B7). |
| Fits the budget | 4 | The recorder exists. New work: the effect-to-call join, the span mapping, about 40 scripted tasks, the check, the gate, and the 50-run audit (Tony, about 1.5 h). All public surfaces; Lemma's SDK is MIT. Not 5 because of the labeled set. |
| Measurable | 4 | Ground truth is each task's end-state oracle, a checker that reads the final work folder and stub logs. It is not the recorder and not the agent. Tony's audit labels back it up. Not 5 because this project writes the oracles (in P2, before any check exists), so Tony's audit is what makes them independent. |

### B. A k-of-n stop rule for rerun-until-pass loops
A stop rule for Workshop's "re-runs until every assertion passes" loop. Promote a fix only when it passes k of n, with k and n chosen from measured band width. Headline: false-promotion rate, single run against k-of-n.

| Criterion | Score | Evidence |
|---|---|---|
| Their customers feel it | 3 | For Lemma: an un-methoded "~2–5%" claim (B4) and one-trace fix verification. No Lemma customer complaint about noise was found. Raindrop's customers feel it more. |
| Not a clone | 4 | Workshop has no stop rule (repo `435670a`). Braintrust averages trials with no rule. Langfuse has no repetitions. |
| Tony has proof | 4 | derm's k-of-3 design and "Tasks passed k of k / 1 of k" columns (`tests/measure/results/summary.md`). |
| Fits the budget | 5 | Small: a rule, a simulator and reruns on the box. |
| Measurable | 4 | Ground truth: each seeded fix's true pass rate from many reruns (for example 30). The rule does not produce that. |
| **Total** | **20** | |

### C. Effect grader for RL environments
The recorder as a grader that checks what the agent did, packaged as a verifiers environment and run against Karotte's hardening as a reward-hack test. Headline: share of seeded reward hacks caught.

| Criterion | Score | Evidence |
|---|---|---|
| Their customers feel it | 2 | Lemma's surface is production monitoring: "It does not offer offline evaluation." Only the `archipelago` repo touches RL environments. |
| Not a clone | 3 | Karotte already hardens graders (kills processes, rejects hostile files). Verifiers graders already read the end-state filesystem. Only the effect log is new. |
| Tony has proof | 4 | Same recorder as A. derm's evidence suite seeds hidden effects of exactly this kind. |
| Fits the budget | 3 | Two outside frameworks to package for, one of them changing (v0 to v1). |
| Measurable | 4 | Seeded hacks with a known answer. |
| **Total** | **16** | |

**Pick: A (22).** B is folded into A as its secondary table, the band gate. It is not the headline. C is left to the reuse list.
