### SL-P5-r1-S1: the agent can write the stub log, which is ground truth, and SECURITY.md T-7 says it cannot fake the ground truth

- **Evidence:**
  - `harness/run-one.mjs:76` puts the stub log at `<FORGE_TMP>/runs/<run>/stub.jsonl`. That is the parent of the agent's work folder (`:70`), so the agent can reach it as `../stub.jsonl`.
  - `tests/integration/stub-server.mjs:32` appends to that file for each request, and `oracle/evaluate.mjs:97` reads it at the end.
  - The PR's own T-7 text says that under srt "the agent **can** reach its trace ... and the results folder".
  - It then says "The ground truth does not read the trace (the oracle reads the end state and the stub log), so only the check's labels could be faked". The stub log sits in the same folder as the trace.
- **Probe:** the round 2 test `main: what the agent writes into the stub log does not reach the oracle or the audit` runs a scripted agent that appends a forged `{"stub":"forged",...}` line to `../stub.jsonl`.
  - On `db18311`'s `harness/` and `stub-server.mjs`, that test fails: the forged line reaches the run artifact, which is what the oracle and Tony's audit packet read.
- **Fix (applied):**
  - `startStubs` keeps an in-memory copy of the log (`entries()`).
  - `runOne` rewrites `stub.jsonl` from that copy after the stubs close and before the oracle runs.
  - T-7 now says what the agent can still reach: the trace, and files under `results/`.

### SL-P5-r1-E1: an E0 cut by the time limit is frozen as E0, and the next dispatch skips E0 and exits 0

- **Evidence:**
  - `harness/main.mjs:186-187` writes the rows to `results/e0-dev.jsonl` whether or not the stage completed.
  - `:346-348` then skips E0 forever once that file exists ("never rerun or overwritten").
  - The same happens when the judge cannot be reached: every row gets `gt_label: null`, and the file is still frozen.
  - The PR puts E0 (240 runs, an estimate) at most of the 720-minute job, so a cut is likely.
- **Repro on `db18311`:** scripted agent, sl06, one repeat. Run 1 uses `SL_MAX_MINUTES=0`, run 2 the default:

  ```
  max=0 exit=1 rows=0
  e0: 0 runs (**stopped at the time limit; incomplete**).
  max=660 exit=0 rows=0
  e0: results/e0-dev.jsonl already exists; E0 is never rerun or overwritten.
  ```
- **Fix (applied):**
  - A stage writes its final file only when every planned run finished and the judge answered every run (an unparsable answer counts as an answer).
  - Otherwise the rows go to `results/<name>.partial.jsonl`, and eval.sh exits 1.
  - Each dispatch is a fresh checkout (forge `eval.yml`: checkout at the sha, upload of `results/`), so the next dispatch, after the partial file is committed, resumes by (task, agent, version, repeat). It re-judges only the runs the judge missed.
  - Two tests cover this: the time-limit case, and judge-down followed by a resume at a later sha.

### SL-P5-r1-E3: two E1 runs at one commit share run ids and artifact files

### SL-P5-r1-E4: runs whose recording failed are dropped from recall instead of counted as misses

- **Evidence:**
  - `harness/score.mjs:259` keeps only rows with a non-null `gt_label` **and** a non-null label from the labeler. A run where `record()` threw (`run-one.mjs:91`, `check_label: null`) therefore leaves both the numerator and the denominator.
